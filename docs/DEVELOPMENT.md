# Разработка

## Начало работы

```powershell
git status --short
npm run check
npm start
```

Сервер работает на `http://127.0.0.1:4173`. Другой порт:

```powershell
$env:PORT=8080
npm start
```

Используйте Git для веток и контрольных точек. Не создавайте внутри проекта
папки с ручными копиями, старые версии файлов или промежуточные экспорты.

## Обычная задача

1. Найти точку правды через `rg`.
2. Изменить минимальный набор файлов одной подсистемы.
3. Добавить или обновить профильный тест.
4. Запустить профильный `node tests/<имя>unit.js`.
5. Выполнить `npm run check`.
6. Для UI, графики, звука и ввода проверить игру в браузере.
7. Обновить относящуюся к изменению документацию.

## Новые файлы

Новый JS помещается в `src/game/`, новый CSS — в `src/styles/`. Подключите его
в `index.html` до первого потребителя и сохраните порядок зависимостей.

Новый runtime-ассет должен быть финальным, лежать в `assets/`, иметь прямую
ссылку из JS/CSS и попасть в manifest после `npm run assets:manifest`.

## Локальные QA-функции

- `DEV_ZONE` — пустая тестовая арена.
- `K` — Spawn Menu.
- `L` — тестовая выдача карточек.
- `F3` — диагностическая панель.
- `P` — быстрая пауза; `Escape` — полные настройки паузы.

Тестовые действия DEV_ZONE не должны изменять постоянный профиль.

## Передача результата

Передавайте всю папку проекта. Минимальный запускаемый runtime состоит из
`index.html`, `src/` и `assets/`; для дальнейшей разработки также нужны
`tests/`, `tools/`, `docs/`, `package.json` и `run-all.js`.
