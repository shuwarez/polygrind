# Grim Grind

Grim Grind — одиночная top-down action RPG на Canvas 2D. PolyGrind остаётся
техническим названием репозитория и автономного файла `PolyGrind.html`.

Игра не требует сборки, сервера или npm-зависимостей: весь код, стили, шрифты и
графика встроены в один HTML-файл.

## Играть и скачать

- [Последний автономный билд](https://github.com/shuwarez/polygrind/releases/latest)
- [GitHub Pages](https://shuwarez.github.io/polygrind/)

Для локального запуска откройте `PolyGrind.html` в актуальном Chrome, Edge или
Firefox. Интернет и соседние файлы игре не нужны.

## Что находится в репозитории

| Путь | Назначение |
| --- | --- |
| `PolyGrind.html` | Единственный runtime-файл игры: UI, механики, баланс, локализация и встроенные ресурсы. |
| `HANDOFF.md` | Единственная техническая передача: архитектура, точки правды, инварианты и порядок проверки. |
| `GRAPHICS_AUDIT.md` | Актуальные требования к runtime-графике и повторяемой упаковке ресурсов. |
| `optimize_graphics.py` | Детерминированная подготовка и установка компактных индексированных PNG. |
| `harness.js`, `*unit.js`, `run-all.js` | Node-харнесс, юнит-проверки, симуляции и диагностические замеры. |
| `.github/workflows/deploy.yml` | Публикация `PolyGrind.html` на GitHub Pages при push в `main`. |

В репозитории намеренно нет датированных balance/handover-отчётов. Одноразовые
замеры быстро устаревают и остаются локальными результатами инструментов или в
истории Git. Текущее поведение определяют код и зелёная регрессия.

## Обязательный порядок работы

1. Для новой сессии создаётся новая timestamp-папка в указанном заказчиком
   каталоге. Предыдущая рабочая копия не переиспользуется и не перезаписывается.
2. Перед первой правкой каждой новой задачи создаётся локальный снимок:

   ```text
   old versions/YYYY-MM-DD_HH-mm-ss_before-<краткое-описание>/
   ```

   В снимке обязательны текущий `PolyGrind.html` и `README.txt` с датой,
   причиной, веткой и коммитом. Затрагиваемые служебные файлы сохраняются рядом.
3. `old versions/` остаётся локальным архивом: папку нельзя добавлять через
   `git add -f`, включать в коммит, release или другой пакет для GitHub.
4. Правки большого автономного HTML делаются небольшими патчами с проверяемым
   контекстом. Массовая замена обязана проверять, что каждый якорь уникален.
5. Любой новый видимый текст сразу получает русскую и английскую версии.

Подробные технические правила находятся в `HANDOFF.md`.

## Проверка

Нужен Node.js 18 или новее; сторонние пакеты не устанавливаются.

```powershell
node run-all.js
```

Успешный результат — все наборы завершились со статусом `OK`, итог содержит
`всё зелёное`, а проверка порядка `recalc()` сообщает, что нарушений нет.
`run-all.js` всегда запускает полную регрессию. Для последовательной диагностики:

```powershell
$env:RUN_ALL_JOBS=1
node run-all.js
```

Проверка синтаксиса встроенного JavaScript:

```powershell
node -e "const fs=require('fs');const h=fs.readFileSync('PolyGrind.html','utf8');[...h.matchAll(/<script[^>]*>([\s\S]*?)<\/script>/gi)].forEach(x=>new Function(x[1]));console.log('Syntax OK')"
```

## Служебные меню QA

- `L` — тестовая выдача карточек.
- `K` — Spawn Menu для обычных врагов, вариантов элиты и боссов.

Оба меню работают только внутри текущего забега и ставят игру на паузу.

## Графика

Новые растры до встраивания обрезаются по фактической альфе, уменьшаются до
реального экранного бюджета и переводятся в индексированную палитру. Цель проекта
— не более 16 индексов вместе с прозрачностью. Пол повторно не оптимизируется.

Полные лимиты, маршруты data URI и команды упаковщика описаны в
`GRAPHICS_AUDIT.md`.
