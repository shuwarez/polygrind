# Grim Grind

Grim Grind — одиночная top-down action RPG на Canvas 2D. PolyGrind остаётся
техническим названием репозитория и автономного файла `PolyGrind.html`.

Игра не требует сборки, сервера или npm-зависимостей: весь код, стили, шрифты и
графика встроены в один HTML-файл.

## Играть и скачать

- [Последний автономный билд](https://github.com/shuwarez/polygrind/releases/latest)
- [GitHub Pages](https://shuwarez.github.io/polygrind/)

Для локального запуска откройте `PolyGrind.html` в актуальном Chrome, Edge или
Firefox. Интернет и соседние файлы игре не нужны.

## Что находится в репозитории

| Путь | Назначение |
| --- | --- |
| `PolyGrind.html` | Единственный runtime-файл игры: UI, механики, баланс, локализация и встроенные ресурсы. |
| `HANDOFF.md` | Единственная техническая передача: архитектура, точки правды, инварианты и порядок проверки. |
| `GRAPHICS_AUDIT.md` | Актуальные требования к runtime-графике и повторяемой упаковке ресурсов. |
| `optimize_graphics.py` | Детерминированная подготовка и установка компактных индексированных PNG. |
| `portal_assets/` | Прозрачный ImageGen-master портала и описание воспроизводимой 16-кадровой упаковки. |
| `legacy_boss_assets/` | Исходные референсы, прозрачные листы и lossless WebP для визуального обновления 14 прежних боссов. |
| `harness.js`, `*unit.js`, `run-all.js` | Node-харнесс, юнит-проверки, симуляции и диагностические замеры. |
| `.github/workflows/deploy.yml` | Публикация `PolyGrind.html` на GitHub Pages при push в `main`. |

В репозитории намеренно нет датированных balance/handover-отчётов. Одноразовые
замеры быстро устаревают и остаются локальными результатами инструментов или в
истории Git. Текущее поведение определяют код и зелёная регрессия.

## Обязательный порядок работы

1. Для новой сессии создаётся новая timestamp-папка в указанном заказчиком
   каталоге. Предыдущая рабочая копия не переиспользуется и не перезаписывается.
2. Перед первой правкой каждой новой задачи создаётся локальный снимок:

   ```text
   old versions/YYYY-MM-DD_HH-mm-ss_before-<краткое-описание>/
   ```

   В снимке обязательны текущий `PolyGrind.html` и `README.txt` с датой,
   причиной, веткой и коммитом. Затрагиваемые служебные файлы сохраняются рядом.
3. `old versions/` остаётся локальным архивом: папку нельзя добавлять через
   `git add -f`, включать в коммит, release или другой пакет для GitHub.
4. Правки большого автономного HTML делаются небольшими патчами с проверяемым
   контекстом. Массовая замена обязана проверять, что каждый якорь уникален.
5. Любой новый видимый текст сразу получает русскую и английскую версии.

Подробные технические правила находятся в `HANDOFF.md`.

## Проверка

Нужен Node.js 18 или новее; сторонние пакеты не устанавливаются.

```powershell
node run-all.js
```

Успешный результат — все наборы завершились со статусом `OK`, итог содержит
`всё зелёное`, а проверка порядка `recalc()` сообщает, что нарушений нет.
`run-all.js` всегда запускает полную регрессию. Для последовательной диагностики:

```powershell
$env:RUN_ALL_JOBS=1
node run-all.js
```

Проверка синтаксиса встроенного JavaScript:

```powershell
node -e "const fs=require('fs');const h=fs.readFileSync('PolyGrind.html','utf8');[...h.matchAll(/<script[^>]*>([\s\S]*?)<\/script>/gi)].forEach(x=>new Function(x[1]));console.log('Syntax OK')"
```

## Камера

Игровой мир рисуется с масштабом `0.95`, поэтому по ширине и высоте видно примерно
на 5,3% больше пространства. Камера не имеет упреждения, инерции или отдельного
смещения: при обычном движении, рывке и отбрасывании герой всегда остаётся точно
в центре экрана. Масштаб не применяется к DOM HUD, экранному Boss HUD и виньетке.

`prepareCameraFrame()`, `screenToWorld()` и `worldToScreen()` являются единым
контрактом для всех Canvas-проходов, culling и управления мышью. Не вычисляйте
координаты курсора отдельным вычитанием `W/2`/`H/2`.

## Служебные меню QA

- `DEV_ZONE` слева сверху в главном меню сразу открывает пустую тестовую арену
  базового Лучника с клавиатурным управлением. В ней нет волн, боссов и портала;
  `K` используется для создания существ и находок, `L` — для выдачи карточек.
  Тестовые убийства созвездий, золото, рекорд и смерть не записываются в
  постоянный профиль.
- `L` — тестовая выдача карточек.
- `K` — Spawn Menu для обычных врагов, вариантов элиты, боссов и всех находок:
  34 босса, 93 предмета, семь книг и пять типов тотемов. Существа появляются в 100–250
  единицах от героя, находки — на земле в радиусе 100 единиц и попадают в
  инвентарь только после обычного подбора.

Двадцать новых боссов из Word-handoff встроены как штатные `BOSS_TYPES`. Их
процентные спецатаки используют общий событийный каркас: предупреждение и удар
разделены, поэтому частота кадров не меняет тайминги. Базовые и четыре
необходимых атакующих листа хранятся внутри HTML в lossless WebP 256×96.

Все 14 прежних боссов также переведены на четырёхкадровые lossless WebP-листы
`256×96` и получили отдельные атакующие анимации. Земляные удары, приземления,
таран, кровавый крест и призывы дополнены самостоятельными четырёхкадровыми
эффектами; точные круги, конусы и полосы телеграфов при этом сохранены.

Оба меню работают только внутри текущего забега и ставят игру на паузу.

## Пауза

- `P` — быстрая пауза: игровой мир остаётся видимым без затемнения, поверх него
  выводится только надпись `PAUSED`. Повторное `P` продолжает игру.
- `Escape` — полное меню паузы с настройками звука и завершением забега.

## Графика

Новые растры до встраивания проверяются по контракту своего семейства. Общая цель
— не более 16 индексов вместе с прозрачностью; предметы, книги и ранги тотемов
являются отдельными RGBA PNG 128×128 с максимумом 32 цветов и бинарной альфой.
Для экипировки дополнительно встраиваются производные индексированные PNG
`24×24`: они используются только на полу. Окно находки, инвентарь, HUD и магазин
всегда показывают исходную каноническую версию `128×128`.
В окне получения предмета эта версия выводится в масштабе 1,5 относительно
прежнего размера и окружена 70 CSS-искрами и пятью слоями ореола. Эффект
изолирован от игрового Canvas и не создаёт боевых объектов или таймеров.
Пол представлен десятью бесшовными индексированными PNG `512×512`: пять
вариантов из handoff и пять дополнительных материалов. Все они встроены в
`FLOOR_TILE_DATA`, а рабочие копии лежат в `floor_textures/`. `buildFloor()`
выбирает один вариант отдельным RNG, поэтому поверхность не меняется внутри
этажа и не сдвигает игровую последовательность врагов или наград. Подготовка,
выравнивание яркости, проверка швов и повторное встраивание выполняются через
`prepare_floor_textures.py`.

Полные лимиты, маршруты data URI и команды упаковщика описаны в
`GRAPHICS_AUDIT.md`.
