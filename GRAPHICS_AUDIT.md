# PolyGrind — правила runtime-графики

Этот файл описывает текущее устройство и обязательный бюджет графики. Это не
хронология оптимизаций: старые размеры и промежуточные отчёты хранятся в истории
Git, а не переносятся в каждый свежий клон.

Пол (`FLOOR_TILE_DATA`) является отдельным семейством: десять бесшовных
индексированных тайлов `512×512`, подготовленных с одинаковой яркостью и
встроенных в автономный HTML. Их нельзя случайно пересобирать режимами других
графических каталогов.

## Источники внутри HTML

Все runtime-изображения встроены в `PolyGrind.html` как data URI. Пиксельные
каталоги в основном используют PNG, а крупные нормализованные листы боссов и
фоны — lossless/quality WebP. Основные каталоги:

| Каталог | Содержимое |
| --- | --- |
| `HERO_SPRITE_DATA` | Четыре героя, по четыре кадра ходьбы. |
| `SUBCLASS_HERO_SPRITE_DATA` | Двенадцать подклассов, по восемь кадров ходьбы строго вправо 36×36; базовые герои остаются fallback. |
| `CLASS_FRAME_DATA` | Четыре классовые рамки главного меню 280×390. |
| `SKILL_CARD_FRAME_DATA` | Пять цветных RGBA-рамок карточек навыков 304×194: обычная, редкая, эпическая, ключевая и кровавая. |
| `ENEMY_SPRITE_DATA`, `ELITE_SPRITE_DATA` | Обычные враги и варианты элиты. |
| `BOSS_SPRITE_DATA` | 34 уникальных четырёхкадровых lossless WebP-листа 256×96: 14 прежних и новая двадцатка. |
| `BOSS_ATTACK_SPRITE_DATA` | 18 четырёхкадровых lossless WebP-листов явных атакующих состояний: все 14 прежних боссов и четыре босса новой двадцатки. |
| `LEGACY_BOSS_EFFECT_SPRITE_DATA` | Шесть четырёхкадровых lossless WebP-листов 384×96 для ударов, приземлений, тарана, кровавого креста и призывов прежних боссов. |
| `CORPSE_SPRITE_DATA` | 30 статичных трупов: 4 обычных, 12 элитных и 14 боссов. |
| `CORPSE_PUDDLE_DATA` | Один индексированный атлас шести кровавых луж 384×64. |
| `MINION_SPRITE_DATA` | Пять видов свиты Некроманта. |
| `LOOT_SPRITE_DATA` | Четырёхкадровые опыт/золото и семь канонических статичных книг 128×128 для UI. |
| `BOOK_FLOOR_SPRITE_DATA` | Семь отдельных производных книг 24×24 только для пола игрового мира. |
| `RARE_ITEM_SPRITE_DATA` | 93 отдельных предмета 128×128: амулеты, перчатки, ботинки, кольца и реликвии. |
| `RARE_ITEM_FLOOR_SPRITE_DATA` | 93 производных индексированных предмета 24×24 только для пола игрового мира. |
| `TOTEM_SPRITE_DATA` | Пять тотемов, по отдельному PNG 128×128 для каждого из четырёх рангов. |
| `PLAYER_PROJECTILE_DATA` и отдельные projectile-константы | Снаряды игрока, врагов и боссов. |
| `MAGE_ABILITY_SPRITE_DATA` | Эффекты способностей Мага. |
| `ENEMY_STATUS_ICON_DATA` | Семь элементальных состояний врага одним листом 112×16. |
| `FLOOR_TILE_DATA` | Десять бесшовных индексированных поверхностей 512×512: пять handoff-вариантов и пять дополнительных. |
| `FLOOR_PORTAL_SPRITE_DATA` | Портал завершения этажа: 16 индексированных кадров бесшовного вихря 128×128 в листе 2048×128. |
| `CONSTELLATION_SPRITE_DATA` | Иконки созвездий. |
| CSS-фон `#constellations` | Статичная астральная обсерватория WebP 1280×853; интерактивные элементы поверх неё остаются HTML/Canvas. |
| `GRIM_GRIND_LOGO_STRIP`, `GRIM_GRIND_TORCH_STRIP` | Логотип и факелы главного меню. |

Каждый data URI загружается один раз и переиспользуется всеми потребителями
своего назначения. Предметы и книги намеренно имеют две версии: компактную
`24×24` только для пола и каноническую `128×128` для окна находки, HUD,
инвентаря и сводки. Тотем использует одну каноническую версию на ранг.

Если `Image` ещё недоступен, допустим лёгкий Canvas-fallback. Он не является
второй полноценной художественной версией ассета.

## Обязательный бюджет

| Тип | Бюджет исходного кадра для runtime |
| --- | ---: |
| Герой | 32×32 |
| Герой подкласса | 36×36, восемь кадров в листе 288×36 |
| Классовая рамка главного меню | 280×390, один статичный индексированный PNG |
| Рамка карточки навыка | RGBA 304×194, один статичный PNG на редкость; вывод через CSS 9-slice |
| Обычный враг | 40×40 |
| Крупный обычный враг | 48×48 |
| Элита | обычно 48×48 |
| Босс | минимальный достаточный; текущий ориентир 64×96 |
| Обычный миньон | 24×24 |
| Индикатор элементального состояния | 16×16 |
| Поверхность пола | отдельный индексированный PNG 512×512, ≤96 цветов, <220 КБ, точное совпадение противоположных краёв |
| Портал завершения этажа | 16 кадров 128×128 в листе 2048×128; runtime-вывод 166×166 |
| Предмет | отдельный RGBA PNG 128×128, ≤32 цвета, бинарная alpha |
| Книга | канонический статичный RGBA PNG 128×128 для UI и отдельный индексированный PNG 24×24 для пола |
| Тотем | отдельный RGBA PNG 128×128 на каждый ранг, ≤32 цвета, бинарная alpha |
| Снаряд или монета | 4–12 px по наибольшей стороне, если механика не требует большего телеграфа |
| Эффект области | минимальная ячейка, масштабируемая до фактического AoE |
| Эффект прежнего босса | четыре кадра 96×96 в листе 384×96; только визуальный слой поверх точного телеграфа |
| Брызги крови | четыре кадра 64×64 в одном листе 256×64 |
| Декали крови | восемь ячеек 64×64 в одном атласе 256×128 |
| Труп | 50% размера handoff: 42–72 px по ширине, полноцветный RGBA |
| Лужа под трупом | 64×64, шесть ячеек в одном атласе 384×64 |
| Фон обсерватории созвездий | WebP 1280×853, один статичный ресурс около 53 КБ |

Босс на экране должен оставаться не меньше чем в 2,5 раза выше героя. Коллизия и
экранный силуэт задаются отдельно.

Для каждого нового растра обязательны:

- обрезка до фактической альфа-области с минимальным безопасным запасом;
- удаление запечённого фона до уменьшения;
- минимальное разрешение относительно фактического экранного размера;
- индексированная PNG-палитра максимум 256 цветов, цель проекта — 16 индексов
  вместе с прозрачностью;
- жёсткая или контролируемая альфа без случайного полупрозрачного мусора;
- отсутствие пустых кадров, неиспользуемых фаз и исходников «про запас»;
- `imageSmoothingEnabled=false` для пиксельной графики;
- отдельное хранение механического радиуса, чтобы оптимизация текстуры не меняла
  баланс.

### Контракт вариаций пола

Рабочие PNG находятся в `floor_textures/` и одновременно встроены в массив
`FLOOR_TILE_DATA`. Порядок фиксирован: `slate`, `cracked`, `damp`, `temple`,
`basalt`, `iron`, `ash`, `crystal`, `forge`, `frost`. Каждый файл обязан иметь
размер `512×512`, индексированный color type `3`, яркость в диапазоне `40–43`,
нулевую ошибку между левым/правым и верхним/нижним краями и размер менее 220 КБ.

Воспроизводимая подготовка выполняется так:

```powershell
python prepare_floor_textures.py <каталог-floor_01..floor_10> floor_textures `
  --preview <contact_3x3.png> --embed-html PolyGrind.html
```

Скрипт уменьшает исходники до `512×512` без сглаживания, выравнивает яркость,
плавно замыкает края, квантует до 96 цветов и обновляет только отмеченный блок
data URI. В runtime все `Image` и `CanvasPattern` создаются один раз при загрузке.
`buildFloor()` выбирает индекс ровно один раз отдельным от `Math.random` RNG;
все `CANVAS_RENDER_PASSES` текущего этажа используют один `floorPattern`.
Если выбранный тайл ещё не готов, используется первый готовый pattern, а при
полном отсутствии изображений сохраняется Canvas-сетка.

### Единый контракт предметных иконок 128×128

Предметные каталоги являются контролируемым исключением из общей цели в 16
палитровых индексов. Итоговый handoff содержит 120 оригинальных RGBA PNG:
93 предмета, семь книг и двадцать отдельных рангов тотемов. Для каждого файла
обязательны точный размер 128×128, не более 32 уникальных RGBA-кортежей вместе с
прозрачным цветом, бинарная alpha (`0`/`255`) и непустой силуэт.

Поддерживаемый путь проверки и установки:

```powershell
$env:PYTHONUTF8=1
python optimize_graphics.py `
  --item-icon-bundle <каталог-handoff> `
  --validate-item-icons-128

python optimize_graphics.py `
  --item-icon-bundle <каталог-handoff> `
  --install-item-icons-128

# Пересобрать наземные копии из уже встроенных канонических предметов и книг:
python optimize_graphics.py --install-item-floor-sprites-24
```

Установщик требует `catalog_manifest.json`, сверяет точное покрытие runtime-ключей
и наличие ровно 120 PNG без лишних файлов. В `PolyGrind.html` переносятся
исходные PNG-байты: для канонического UI-каталога ресайз, повторная квантизация и
изменение alpha запрещены. Одновременно из 93 предметов и семи книг воспроизводимо
строятся `RARE_ITEM_FLOOR_SPRITE_DATA` и `BOOK_FLOOR_SPRITE_DATA`: каждый силуэт
вписывается в прозрачный холст 24×24, палитра сокращается до семи непрозрачных
цветов, Canvas smoothing отключён.
Отсутствующий ключ является ошибкой установки и теста; Unicode-значки из игровых
каталогов не используются как графический fallback.

`LOOT_SPRITE_META` задаёт каноническим UI-книгам `frameW=frameH=drawW=drawH=128`.
`lootSpriteFrame()` возвращает для книги индекс `0` и прямоугольник `0,0,128,128`,
поэтому крупная UI-книга неподвижна и не зависит от `G.time`. На полу
`drawBookFloorSprite()` выбирает отдельный 24×24 PNG по ключу книги. Каждый ранг
тотема остаётся отдельным файлом `rank1`…`rank4`, а не листом.

На земле предметы и книги выводятся 24×24, а текущие тотемы — 128×128; smoothing
отключён. Это только визуальный размер: `o.r`, радиус подбора, координаты, правила
выпадения и баланс не меняются. В компактном UI канонический источник уменьшается CSS, а окно
получения показывает его крупно через `pickupRevealHTML()` с одной CSS-пульсацией
и 14 искрами. Декор не создаёт RAF, таймеров или объектов игрового цикла и
замирает при `prefers-reduced-motion`.

Готовые листы подклассов являются уже нормализованным источником: режим
`--install-subclass-hero-sprites` читает их из каталога ассетов, сверяет
фиксированные SHA-256, `P`-mode, размер 288×36, прозрачность, не более 192
используемых индексов и восемь непустых кадров движения 36×36. Ресэмплинг и повторная
квантизация в этом режиме запрещены; в HTML записываются исходные PNG-байты.

Крупное превью модели в главном меню и выборе подкласса не является отдельным
ассетом: оно обязано использовать тот же data URI из `SUBCLASS_HERO_SPRITE_DATA`.
Размер превью — 108×108, то есть точный масштаб 3× от кадра 36×36, с
`image-rendering:pixelated`. Создание облегчённой preview-копии, повторное
уменьшение или отдельная квантизация для меню запрещены: экономия нескольких
килобайт не оправдывает потерю лица, оружия и силуэта персонажа.

Рамки карточек навыков являются готовыми lossless-источниками 304×194. Карточка
в runtime имеет ширину 270 px и переменную высоту, поэтому физический ресайз до
одного фиксированного прямоугольника запрещён: он либо искажает углы, либо
обрезает длинный русский текст. `SKILL_CARD_FRAME_DATA` хранит исходные PNG-байты,
а `.level-card-grid .card::before` выводит их через CSS 9-slice. Растягиваются
только прямые рейки; рамка не создаёт `Image`, таймеров, фильтров или объектов
игрового цикла и не применяется к карточкам классов и магазина.

Логотип главного меню — намеренное исключение из цели в 16 индексов: центральная
вывеска хранит 63 непрозрачных цвета и прозрачность, по восемь кадров 512×144.
Это сохраняет мелкие металлические детали при крупном выводе; исходный фон всё
равно удаляется, а лист остаётся индексированной оптимизированной PNG.

Экран созвездий использует один сгенерированный RGB-источник 1536×1024 только
как исходник упаковки. Режим `--install-constellation-observatory` сверяет его
SHA-256, уменьшает до 1280×853 и воспроизводимо кодирует в WebP quality 62.
Runtime хранит ровно один 53 110-байтный data URI; исходный PNG остаётся локальным
в `assets/generated/` и не публикуется. Шесть обычных и специальных путей по-прежнему
переиспользуют игровые листы врагов и два компактных листа Элиты/Босса.

Рамки классов и подклассов — второе контролируемое UI-исключение: они выводятся
крупно и используют палитру до 128 RGBA-индексов с таблицей прозрачности tRNS.
Рамки подклассов имеют точный размер 320×400; расширена только внутренняя область,
а углы и орнаменты не масштабируются. Так сохраняются металлические градиенты и
сглаженные края, но полноцветные RGBA PNG в runtime не допускаются. Установщик
проверяет готовые индексированные байты и не выполняет повторный ресэмплинг.

Эффект, который читаемо выражается Canvas-примитивом, не получает отдельную
текстуру. Частицы остаются небольшими примитивами с общим потолком количества.

Кровь — контролируемое исключение для направленной анимации и разнообразных
следов. `BLOOD_SPRITE_DATA` содержит четыре готовых RGBA-листа с 4–9 цветами:
две анимации 256×64, критический разлёт 128×32 и атлас декалей 256×128,
суммарно 4 274 байта PNG. Режим
`--install-blood-assets` сверяет SHA-256, геометрию, RGBA, прозрачный фон и
потолок 16 цветов, затем встраивает исходные байты без ресэмплинга.

Постоянные следы не хранятся массивом игровых объектов: они один раз наносятся
на `G.bloodGroundCanvas` размером с арену. В кадре копируется только видимый
фрагмент. Временный `G.bloodFx` ограничен 600 объектами; при переполнении эффект
сразу превращается в декаль. `BLOOD_CFG.density=2` удваивает капли и слои
направленных брызг; лимит запечённых следов также поднят до 1800. Мелкие брызги
крита запечены в один четырёхкадровый лист: каждый из двух слоёв остаётся одним
объектом и одним `drawImage`, а не отдельной россыпью частиц. Холст и массив очищаются в `buildFloor()`, поэтому
пауза, меню и смерть не стирают историю текущего этажа.

Трупы — отдельное полноцветное исключение из палитровой цели. Установщик
проверяет 30 исходных SHA-256 из handoff, очищает нейтрально-белый matte на
прозрачном краю, выполняет alpha-aware уменьшение ровно до 50% и повторяет
очистку после ресэмплинга. Итоговые PNG остаются RGBA; белый ореол нельзя прятать
CSS-фильтром или сглаживанием Canvas.

## Анимация и кадры

- Базовые герои используют четыре кадра ходьбы, подклассы — восемь; отдельные
  ряды атак и призыва не хранятся.
- Исходная ориентация всех подклассов — строгий профиль вправо. Поворот к цели
  выполняется только горизонтальным зеркалированием готового листа; смешанные
  фронтальные, диагональные и направленные в центр кадры не допускаются.
- После выбора подкласса рендер предпочитает его лист, но до загрузки или при
  отсутствии ресурса использует соответствующий базовый класс. Базовая модель
  выводится 48×48, подклассовая — 64×64 для читаемости деталей; механический
  `p.r` не меняется. Восьмикадровый цикл сохраняет длину прежнего полного шага.
- Обычные враги и свита меняют кадр по пройденному пути и замирают вместе с
  сущностью.
- Направление движения меняется горизонтальным зеркалированием. Спрайт не
  вращается, если вращение не является частью конкретного снаряда.
- Одинаковые снаряды используют общий таймер кадра, а не отдельный таймер на
  каждый экземпляр.
- Портал бесшовно зацикливает 16 полноразмерных кадров 128×128 слева направо по
  80 мс. Архитектурное кольцо остаётся неподвижным, а внутренний вихрь вращается
  и пульсирует. Лист индексирован с мягкой alpha-кромкой и рисуется
  размером 166×166 с отключённым smoothing и нижним центральным якорем. Коллизия
  перехода хранится отдельно в `G.portal.r` и не меняется вместе с артом.
- Процедурные 96 энергетических искр не входят в текстуру и отсекаются вместе с
  расширенным радиусом портала. Приглушённая направляющая стрелка принадлежит `worldHud`,
  поэтому всегда остаётся рядом с героем, даже когда портал за экраном.
- Главное меню показывает первый статичный кадр и меняет подкласс раз в четыре
  секунды через единый RAF меню. Экран выбора подкласса продолжает листать восемь
  кадров. При `prefers-reduced-motion` остаются первый подкласс и первый кадр.
  Остальной UI показывает стабильный кадр листа, если анимация не добавляет
  полезной информации.

## Повторяемая упаковка

`optimize_graphics.py` является единственным поддерживаемым путём массовой
подготовки и установки встроенных PNG. Скрипт обязан:

1. Проверять входные размеры, кадры и ожидаемые имена.
2. Стабильно обрезать и масштабировать исходники.
3. Писать воспроизводимые результаты в локальную `outputs/`.
4. При установке менять только целевой каталог data URI.
5. Проверять уникальность HTML-якоря и завершаться ошибкой при нуле или нескольких
   совпадениях.
6. Никогда не менять `FLOOR_TILE_DATA` как побочный эффект.

Поддерживаемые семейства режимов можно посмотреть без копирования списка в
документацию:

```powershell
$env:PYTHONUTF8=1
python optimize_graphics.py --help
```

Сюда входят сборка/установка героев, обычных врагов, элиты, боссов, свиты,
снарядов, единого 128×128 handoff предметов/книг/тотемов, крови, цветных рамок
карточек навыков, фона обсерватории созвездий, индикаторов состояний, портала
завершения этажа, эффектов Мага, созвездий и вывески меню. Старые раздельные
режимы предметов 24×24 и четырёхкадровых книг завершаются ошибкой.

Прежние боссы пока воспроизводимо готовятся отдельными узкими инструментами:
`extract_legacy_boss_assets.py`, `prepare_legacy_boss_assets.py` и
`embed_legacy_boss_assets.py`. Их рабочие прозрачные PNG, окончательные WebP и
контактные листы лежат в `legacy_boss_assets/`; в runtime попадают только
каталоги `webp/base`, `webp/attack` и `webp/effects`.

`outputs/` и исходные многомегапиксельные изображения не являются runtime и не
публикуются. В `PolyGrind.html` устанавливаются только окончательные компактные
листы.

## Проверка после изменений

Минимальный набор выбирается по затронутому ресурсу:

```powershell
node herospriteunit.js
node skillframeunit.js
node spriteunit.js
node bossunit.js
node boss20unit.js
node locunit.js
node run-all.js
```

Дополнительно обязательна визуальная проверка в браузере:

- фон действительно прозрачный;
- кадр не обрезан и не прыгает относительно опоры;
- nearest-neighbor масштаб выглядит ожидаемо;
- модель не вращается или не зеркалится ошибочно;
- UI показывает правильный ключ и кадр;
- механический радиус и баланс не изменились.

## Что не хранится в документации

Сравнения «до/после», размеры присланных исходников, даты отдельных оптимизаций и
одноразовые замеры не являются постоянной документацией. При необходимости они
фиксируются в сообщении коммита, задаче или локальном snapshot и остаются
доступны через историю Git.
